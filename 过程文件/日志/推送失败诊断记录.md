# 推送失败诊断记录

**结论：本环境无法完成 GitHub 推送，属环境限制，与仓库/提交无关。**
提交已在本地就绪（`333a422`，分支 `main`），远端 `origin` 已配置且为空仓。
**请在你自己的终端执行一次即可完成：**

```bash
cd D:\workspace\DrawClimateChart
git push -u origin main
```

## 现象

`git push -u origin main` 在**任何**配置下都返回退出码 **128，且不输出任何错误信息**
（stdout / stderr 均为空），远端分支始终为空。

## 排查过程与证据

| 步骤 | 手段 | 结果 |
|---|---|---|
| 1 | 检查凭据是否可取 | `git credential fill` 正常返回 `protocol/host/username/password` 四项 → **凭据本身可用** |
| 2 | 验证错误捕获机制是否正常 | `git push 不存在的远端 main` → 正常捕获 `fatal: '...' does not appear to be a git repository` → **捕获机制没问题** |
| 3 | 对照实验：禁用全部凭据助手 | `git -c credential.helper= push` → 输出可读的 `fatal: could not read Username ... terminal prompts disabled` |
| 4 | 对照实验：启用 `manager` 助手 | `git -c credential.helper=manager push` → **128 且零输出** |
| 5 | 对照组 3/4 对比结论 | **一旦调用凭据助手子进程，git 就静默失败**；不调用时错误信息可读 |
| 6 | `GIT_TRACE=<文件>` | 轨迹停在 `run_command: 'git credential-manager get'` 之后，**助手进程再无返回** |
| 7 | `GIT_TRACE_CURL=<文件>` | 仅发出**未认证**的 `GET /info/refs?service=git-receive-pack` → `401 Unauthorized` → 连接保持 → 之后**没有第二次（带凭据）请求** |
| 8 | 绕过 GCM：把凭据灌入一次性 `git-credential-store` 临时文件 | 仍为 128 零输出（助手子进程仍被调用）；临时文件用完即删，未写入版本库 |
| 9 | 禁用沙箱后重试 | 出现可读错误 `schannel: failed to receive handshake, SSL/TLS connection failed`（走用户代理 `127.0.0.1:7897`） |
| 10 | 沙箱外直连（`-c http.proxy=`） | `ls-remote` 成功（代理与直连均可达，仓库确实为空），但 `push` 仍是 128 零输出，`GIT_TRACE_CURL` 显示同样只发到 401 为止 |
| 11 | 完全绕开凭据助手：把凭据直接内嵌进推送 URL（内存构造，不落盘、不打印） | 仍为 **128 零输出** → **证明与凭据无关** |
| 12 | `git push --dry-run --verbose` | 输出仅到 `Pushing to https://github.com/Houer23/wmo-climate-chart.git` 即中断，**未产生任何 HTTP 请求** |
| 13 | 改用 SSH（`git@github.com`） | 网络正常（能建立连接并返回 `Permission denied (publickey)`），但本机**无任何 SSH 密钥**，不可用 |

## 判定

1. **沙箱内**：网络可达（GitHub 正常返回 401），但 **Git Credential Manager 子进程被沙箱阻断**
   —— 进程启动后无返回，git 因拿不到凭据而终止；此路径下 git 不产出任何错误文本。
2. **沙箱外**：走用户代理或直连时，推送阶段 TLS 握手异常/静默失败；即使把凭据直接内嵌进 URL
   （完全不用凭据助手）仍失败，`--dry-run` 更是在发出任何请求前就中断。
3. 因此可以排除「仓库不存在」「提交有问题」「凭据缺失或失效」三类原因；
   **`git push` 在本执行环境中恒定失败且不给出任何诊断信息**，属环境限制。
4. 两条路径都无法完成推送，因此**改由用户在自有终端执行**（其凭据与网络环境正常，
   `~/.gitconfig` 中已有 GitHub 凭据且 `credential.helper=manager` 可用）。
